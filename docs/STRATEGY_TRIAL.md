# 火山AI固定策略前瞻验收 v3

目的：验证一套固定出单过程是否优于纯赔率基准。不是发布盈利策略，不是实际投注，也不追求每天必须有单。现有平／让平规则、AI研判和实际投注记录保持不变。

## 使用入口

推荐页 → 策略验收。管理员点击“开始AI版30天模拟”登记一次，重复点击不会重置日期或成绩。必须已配置火山方舟，调用会产生API费用。

当前只保留V3，实验ID为 `paper-multi-ark-v3`，包含约3倍二串一和平／让平3场2、3关两类独立方案。页面不再提供V1/V2切换，接口和定时任务也只处理V3；旧版数据留在数据库，不删除、不合并或补算成V3。

- 北京时间14:00以前登记，从当天开始；14:00及以后登记，从次日开始。
- 每天北京时间14:00由独立任务读取当时数据库快照，5分钟为输入捕获容错窗口。先持久化输入，再分批调用火山大模型，每批最多10场。保存实际捕获和AI完成时间，不伪装成14:00整；AI完成时已开始的比赛不进入赛前模拟单。
- 已登记的原18:00版V3执行一次有审计记录的时间迁移：仅接受已知实现指纹和未改动的规则，时间改为14:00，不重置30天日期和已有成绩。14:00以后调整从次日生效；不补跑生效前未冻结的日期。原18:00留档不变，未完成AI任务归档，不重复调用。后续模型代码变更仍按冻结保护暂停，不能借此迁移绕过。
- 未部署或没有启动试验时，不会自动积累记录。程序离线错过窗口的日期只记录“错过”，不拿后来数据补选。
- 30天到期后停止新出单，已留档比赛继续结算。不自动发布、不自动增加金额。

## 已登记的实验规则

这是尚待验证的初始假设，不是已发现的盈利规律。

1. 只扫描当天竞彩日、未开始且距开赛超过10分钟的比赛；数据库采集时间不得晚于决策时间，也不得超过60分钟。
2. 独立调用火山，真实判断每场六项概率、主选、理由、风险。固定Prompt、请求模型、API模式、接口地址及请求参数；不使用已存AI推荐，不加载自动调权或新发布Skill。模型latest别名由供应商维护，不能保证底层模型权重完全锁定，因此同时记录供应商返回的模型名（如提供）。
3. 每场只接受大模型原始主选，本地不因概率更高而改推另一项。低于1.50的主选不参与；融合估计为35%AI概率加65%同市场去水隐含概率，未经过独立概率校准。两个三项概率需各自合计约100%，且与主队正负让球语义一致。
4. 主选融合估计至少45%，估计概率乘赔率至少1.00；需要完整亚盘、大小球及所选市场60分钟内的投注比例，所选结果资金偏离不超过+10个百分点，并且AI未标记严重数据风险。
5. 未通过条件不改用次选。不同比赛两两组合，合计赔率2.8～3.3内，按独立近似组合估计从高到低只保留一张。没有合适组合记未出单，不放宽条件凑单。
6. 约3倍二串一和平／让平2、3关各最多1张，各固定1模拟单位；两种策略同时有单时总模拟投入为2单位，不混成一张单。不倍投，不追损，不落入真实投注或合买分账记录。

### 平／让平独立分支

- 复用同一批火山调用。AI除主选外，还需独立返回普通平、竞彩让平的候选同意/否定及理由。它可以是主选之外的方向，不改动约3倍二串一主选，也不修改现有平／让平雷达规则。
- 只接受AI明确同意的候选。缺少独立评估字段、明确否定、AI失败或严重数据风险时，不以本地概率自动补选。
- 预注册门槛：单项赔率2.50～5.00；融合估计普通平≥28%、让平≥25%；估计概率乘赔率≥1.00；亚盘、大小球、所选市场投注比例及新鲜度要求与主分支一致。本玩法资金偏离不得超过+10个百分点。
- 融合估计仍为35%AI＋65%同市场去水概率。以上是待验证的实验门槛，不是已发现的稳定盈利规律。
- 同场平/让平只保留融合估计较高的一项；让球为0的让平与普通平重复，不另占名额。取3场不同比赛，在独立近似下使“至少中2场”的估计最高；不强制平和让平各占几场，不足3场不凑单。
- 3场2、3关必须展开为3个二串一和1个三串一，共4注；每注0.25模拟单位，合计1单位。两场命中只返对应二串一，三场全中返4注，不能只按一个三串一结算，也不存在单一“总赔率”。
- “有返奖率”和“盈利张数/ROI”分开显示。改期可能使有返奖但仍亏损；全退票按1单位退回，不计入返奖率。各子注均保留冻结价格、结果和返奖。
- 另存纯赔率平／让平基准单，只用相同快照中本玩法市场概率最高的3场作对照，不套AI同意或正期望门槛。

## 冻结、审计与结算

- MongoDB `fae_strategy_trials`：实验日期、完整参数、权重、规则和实现哈希。登记只允许首次插入，不提供覆盖或重置接口。此次时间调整通过规则/代码指纹校验和原子比较更新，保存 `schedule_history`、生效日期与迁移前配置；不会修改每日快照。
- `fae_strategy_trial_days`：每天两类方案各自的模拟单/未出单原因、各自基准单、全部原始输入、AI输出、各场排除理由和快照哈希。通过唯一索引和 `$setOnInsert` 防止重复任务覆盖。平／让平字段为 `draw_ticket`、`draw_baseline_ticket`、`draw_candidates`、`draw_decision`。
- `fae_strategy_trial_ai_jobs`：冻结输入和逐批调用检查点，保存Prompt原文、响应原文、调用ID、返回模型、用量、错误与时间。凭证不入库。每批原子抢占后才能付费调用；成功或失败均不自动重试。进程中断的运行中请求等待超时后记失败，不盲目再扣一次费用。
- `fae_strategy_trial_reviews`：赛果和收益单独更新，不改赛前价格、选项、让球数或快照。报告只接受哈希对应的结算。
- 涉及模型、盘口规则、版本或结算实现的代码改变后，实验暂停新增单。需要新实验版本才能换算法，不把两套规则混算。
- 只用数据库中完场比赛结果结算。改期状态6按赔率1.00处理；两场均结算后才计入财务样本，一场改期会降低票面组合赔率，全退票不计入胜负命中率但计入已结算资金。
- 每分钟检查留档、检查点和结算；输入已冻结的任务可从下一未调用批次恢复。调用失败、配置缺失、响应无效、遗漏或概率矛盾均记录失败，不以确定性引擎降级冒充AI研判。没有登记AI版试验不调用大模型。

## 验收报告

报告包含全部日期（包括未出单、错过窗口、版本暂停）。约3倍二串一与平／让平2、3关分别统计模拟投入和净收益、ROI、最大回撤与纯赔率基准。二串一显示整张命中率；2、3关显示有返奖率、盈利张数、逐注结算。最长连亏按连续负收益张数统计，命中/返奖率排除全退票，财务样本包含全部已结算单。

满5张已结算单后显示固定随机种子重采样的ROI区间。它只描述已有样本，不包含所有跨日相关性、筛选偏差，不能据此保证以后盈利。30天只是观察窗口，不是充足样本或通过证明。

对照策略读取同一时刻、同一可交易比赛宇宙，在≥1.50的各玩法中取每场市场去水概率最高的一项，再按相同赔率范围组一张单，不使用模型门槛。两组出单数量可能不同，需要同时看覆盖天数、收益、波动，不能只挑其中一项比较。

## API

- `GET /api/fae/strategy-trial`：只读V3报告，不运行研判或生成单；显式指定旧版ID返回422。
- `POST /api/fae/strategy-trial/start`：管理员登记，参数固定，重复调用幂等。
- `GET /api/fae/strategy-trial/audit?date=YYYY-MM-DD&experiment_id=paper-multi-ark-v3`：管理员读取某天完整留档及AI调用检查点。

固定Prompt在 `football_ai/strategy_trial_ai.py`，版本与哈希同时存于实验配置。请求超时180秒、输出上限6144 tokens、关闭隐藏思考、自动重试0次，每批最多10场，复用现有ARK环境配置。新增分支共用同一轮调用，但输出内容增加，费用不承诺与旧版相同。

本模式不会写入 `bets` 或投注记录，不会调用投注平台。
